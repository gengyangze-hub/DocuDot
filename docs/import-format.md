# 导入格式说明

导入器（`app/services/importer.py`）的第一原则是**容错**：同一批数据换个写法也得能进来。
四种写法可以混在同一个文件里。

---

## 一、规范化 Markdown（推荐格式）

这也是 AI 预处理的**目标格式**，导出接口产出的就是它，因此「导出 → 改 → 导入」可以闭环。

```markdown
# 库存清单

## STM元器件

| 名称 | 数量 | 位置 | 规格 | 别名 | 备注 |
| --- | --- | --- | --- | --- | --- |
| STM32F103C8T6 | 25 | A柜-1层-盒3 | LQFP48 | F103C8, STM32F103 | 蓝药丸板用 |
| 0.1uF 50V MLCC | 500 | A柜-2层-盒1 | 0805 | 104, 100nF | |

## Steam游戏卡

| 名称 | 数量 | 位置 | 规格 | 别名 | 备注 |
| --- | --- | --- | --- | --- | --- |
| Steam 50元充值卡 | 10 | B柜-抽屉1 | 50元 | 50元卡 | |
```

要点：

- `##` 二级标题就是**分类名**，写什么就是什么（`## 耗材` → 分类「耗材」）。
  **没有内置分类表** —— 分类完全由你（标题 / 分类列）或 AI 决定。
- `###` 及更深的标题是**条目名**，不是分类（那种写法下面通常跟 `- 数量: …` 的键值行）。
- 没有标题、也没写分类列时，记录先落在「未分类」，导入时勾选 AI 归类（`use_ai`）就会自动分好。
- 表头列名可以是**中文或英文的任意常见写法**（见下表），顺序随意，多余的列忽略。
- 「名称」必填，其它留空即可。数量列缺失或写不出数字时按 0 处理并在 `warnings` 里提示。
- 别名列支持 `,` `，` `、` `/` `|` `;` 分隔。

### 表头别名表

| 字段 | 能识别的写法 |
|---|---|
| 名称 | 名称、品名、物品、物品名称、元件、元件名、型号、器件、name、item、part |
| 数量 | 数量、数目、库存、库存数、库存量、个数、件数、qty、quantity、count、stock |
| 位置 | 位置、存储位置、存放位置、库位、货架、货架位、柜子、存放地、location、bin、shelf |
| 分类 | 分类、类别、类型、种类、category、type、kind |
| 规格 | 规格、封装、型号规格、参数、spec、package、footprint |
| 别名 | 别名、标签、别称、又叫、alias、aliases、tags、tag |
| 备注 | 备注、说明、注释、note、remark、comment |
| 单位 | 单位、计量单位、unit |

> 表头识别是「包含」匹配，所以「存放位置(柜-层-盒)」这种带说明的列名也能认出来。
> 一个都没认出来时，退回**固定列序**：`名称 数量 位置 分类 规格 别名 备注 单位`。

## 二、行内式条目

适合随手记，也适合 QQ 里批量发。

```
名称 × 数量 @位置 #别名 #别名 (规格)
```

数量也可以写成 `25个` / `30 片` / `12只`；位置用 `@` 或 `位置:` 引出。

```text
STM32F103C8T6 × 25 @A柜-1层-盒3 #F103C8 #STM32F103 (LQFP48)
0.1uF 50V MLCC × 500 @A柜-2层-盒1 #104 #100nF (0805)
NE555 30个 @C柜-1层 #555 (DIP-8)
```

解析器会把已识别的片段从名称里剔除，剩下的就是名称。以 `-` / `*` / `1.` 开头的行会先剥掉列表符号。

## 三、键值块

每个条目一块，块内是 `键: 值`：

```markdown
### 1N4148
- 数量: 200
- 位置: C柜-2层
- 规格: DO-35
- 别名: 4148

### Steam 50元充值卡
- 数量: 10
- 位置: B柜-抽屉1
- 规格: 50元
```

`###` 三级标题即条目名；块之间用空行分隔。

## 四、Excel / CSV

- 支持 `.xlsx` / `.xlsm`（**不支持旧版 `.xls`**，请另存为 xlsx 或 csv）
- **多工作表**：逐个解析，工作表名直接当分类名（叫「游戏卡」的表 → 分类「游戏卡」）
- 表头可以不在第一行：会扫描前 10 行找命中 ≥2 个字段的那一行
- CSV 自动判断分隔符（逗号 / Tab）
- 编码：UTF-8（带不带 BOM 都行），失败时回退 GBK

生成示例文件：

```bash
python3 scripts/make_sample_xlsx.py samples/sample_inventory.xlsx
```

## 五、AI 预处理流程

### 方式 A：手工转（无需配置 LLM）

```bash
KEY=...
curl -s -H "X-API-Key: $KEY" http://127.0.0.1:8000/api/v1/import/template \
  | python3 -c "import json,sys; print(json.load(sys.stdin)['ai_prompt'])"
```

把这段提示词 + 你的原始资料一起丢给任意大模型（ChatGPT / DeepSeek / Kimi 都行），
让它输出 Markdown，然后：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/import/commit \
  -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -d "$(python3 - <<'PY'
import json
content = open("ai_output.md", encoding="utf-8").read()
print(json.dumps({"filename": "ai_output.md", "content": content, "mode": "merge"}))
PY
)"
```

### 方式 B：服务端调 LLM（一键）

```bash
curl -X POST http://127.0.0.1:8000/api/v1/import/ai \
  -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -d "$(python3 -c 'import json;print(json.dumps({"content": open("samples/sample_messy_input.txt",encoding="utf-8").read(), "mode":"merge"}))')"
```

响应里会带上 `normalized_markdown`（模型整理出的 Markdown）、`preview`（解析结果）、
`result`（落库统计）。**先看 `normalized_markdown` 再决定要不要真的导入**，
或者加 `"dry_run": true` 只试跑。

## 五、JSON

支持三类结构：

**1. 顶层数组**（键名中英文都认，复用表头别名表）

```json
[
  {"名称": "NE555", "数量": 30, "位置": "C柜-1层", "封装": "DIP-8", "别名": ["555", "定时器"]},
  {"name": "AMS1117-3.3", "qty": 50}
]
```

**2. 包一层**：`{"items": [...]}`、`{"components": [...]}`、`{"records": [...]}`、`{"data": [...]}` 都认。

**3. component-inventory 的导出**（本项目的模糊匹配就是参考它的）

```json
{
  "app": "component-inventory",
  "components": [
    {"tags": ["C", "1uF", "16V", "MLCC", "0805"], "stock": {"mode": "coarse", "level": 3}}
  ]
}
```

映射规则：

| 本系统字段 | 来源 |
|---|---|
| 名称 | `tags` 里**非封装**的部分（`C 1uF 16V`）—— 身份信息 |
| 规格 | `tags` 里看起来像封装的标签（`MLCC` / `0805` / `直插` / `2.54` / `5x11mm` …） |
| 数量 | `stock.mode = "coarse"` 时按 **1→10 / 2→50 / 3→200** 映射；`exact` 时用原值 |
| 备注 | 原始粗粒度等级（`原粗粒度库存 level 3（多）`）—— 免得映射出的数字被当成真实库存 |
| 分类 | 交给 AI 归类（见下） |

## 六、导入时的 AI 预处理

导入前会把这批物品**一次性**（不是每条一次）交给大模型，同时完成**规范命名**与**归类**。

### 1. 规范命名

命名规范（写进提示词，可按需修改 `app/services/ai.py:IMPORT_ANALYZE_SYSTEM`）：

> **封装不进名称**：名称只写身份（型号 / 数值带单位 / 介质），封装与规格单独放 `spec` 字段。
> 列表里显示成 `名称（规格）`，所以既不会重复、又能一眼看到封装。

| 规则 | 例子 |
|---|---|
| 名称只写身份，**不含封装** | `C 1uF 16V MLCC 0805` → 名称 `1uF 16V MLCC`、规格 `0805` |
| 去掉类型字母前缀（单位已经说明类型） | `R 10kΩ` → `10kΩ` |
| 中缀小数转标准写法、补规范单位 | `R 4k7` → `4.7kΩ`、`R 1k` → `1kΩ` |
| 中文名统一、大小写统一 | `黄 led` → `发光二极管 黄色`、`排母 3p` → `排母 3P` |
| 型号原文照抄只调大小写 | `stm32f103c8t6` → `STM32F103C8T6` |
| 不带数量/位置/别名进名称 | `10kΩ @C库` → 拒绝 |

同样的规则也适用于手动录入：`入库 100Ω电容 0805 100` 会自动解析成
**名称 `100Ω电容`、规格 `0805`、数量 100**，所以不会再追问一次封装。

**两道安全护栏**（改名是有风险的操作）：

1. **信息保留检查** —— 新名必须包含原名里至少一个「有信息量」的片段（含数字，或折叠后长度 ≥2）。
   所以 `10kΩ 0805` → `电阻`、`NE555` → `555` 这类**丢信息的改名会被直接拒绝**。
2. **原名保留为别名** —— 就算改得不合你意，搜旧写法照样找得到。

### 2. 自动归类

- 优先复用已有分类；**装不下就新建**一个简短通用的中文分类，并立刻生效
- 实测（真实 DeepSeek，混合清单，库里一开始一个分类都没有）：

```
STM32F103C8T6 → STM元器件（新建）    M3 螺丝      → 五金件（新建）
0.1uF 50V     → STM元器件          中性笔       → 文具（新建）
Switch卡带 塞尔达 → 游戏周边（新建）
```

- 不勾选 AI 时记录落在「未分类」，之后跑 `整理` 也能让 AI 归好

- AI 调用失败或返回不合法时**自动退回原值**，绝不挡住导入

开关：QQ 侧 `AI_NORMALIZE_ON_IMPORT` / `AI_CLASSIFY_ON_IMPORT`；HTTP 侧传 `use_ai=true`（默认 false，需要显式开启）。

## 七、导入模式与字段语义

| mode | 已存在（名称+位置+规格 相同） | 不存在 |
|---|---|---|
| `merge`（默认） | 更新数量（快照语义）、合并别名 | 新建 |
| `add` | 数量**累加** | 新建 |
| `replace` | 先清空本次涉及分类下的全部旧记录，再全部新建 | 新建 |

- 物品唯一键 = `名称 + 位置 + 规格`（三者都做归一化后比较）。
  同一个料号放在两个柜子里 = 两条记录，符合仓库实际。
- 每次导入都会写 `import_batches` 批次记录 + 每条物品的 `stock_movements` 流水（`action=import`）。
- `dry_run: true` 时完全不写库，只返回将要发生的变更统计。
