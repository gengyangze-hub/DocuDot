# QQ 官方机器人接入指南

本项目走 **QQ 机器人开放平台**（`bot.q.qq.com`）的 **WebSocket 网关**，不是 OneBot/NapCat 那套。
好处是**不需要公网 IP、不需要回调地址、不需要额外进程**——机器人和 HTTP 服务在同一个进程里，
`uvicorn` 一起来机器人就连上了。

---

## 一、准备凭证

1. 到 [QQ 机器人开放平台](https://bot.q.qq.com/) 注册开发者、创建机器人
2. 在「开发设置」里拿到 **AppID** 和 **AppSecret**
3. 记下沙箱环境是否可用（`QQ_SANDBOX=true` 时走 `sandbox.api.sgroup.qq.com`）

> 群聊/单聊能力需要在平台上申请开通并等待审核。
> 未开通时只能用频道（guild）场景，本项目对频道只做接收不做主动回复。

---

## 二、配置

编辑 `.env`：

```ini
QQ_BOT_ENABLED=true
QQ_APP_ID=你的AppID
QQ_APP_SECRET=你的AppSecret

# 如果你的机器人只有旧式 token 而没有 secret，填这个（优先级低于 secret）
QQ_BOT_TOKEN=

# 沙箱环境（强烈建议先在这里试）
QQ_SANDBOX=true

# 订阅的事件位。默认 = 公开频道消息(1<<30) + 群和单聊消息(1<<25)
QQ_INTENTS=1107296256

# 白名单：留空 = 不限制。多个用英文逗号分隔
# 单聊填 user_openid，群聊填 group_openid
QQ_ALLOWED_USERS=
QQ_ALLOWED_GROUPS=

# 可选：只响应以此前缀开头的消息（例如 "/"），留空则整条消息都解析
QQ_COMMAND_PREFIX=
```

`QQ_INTENTS` 也可以写成表达式，例如 `1<<25 | 1<<30`。

---

## 三、启动与验证

```bash
bash scripts/run.sh
```

看到这样的日志就说明机器人起来了：

```
DocuDot 启动完成：库=/你的数据目录/inventory.db，物品=0 种，QQ 机器人=开，LLM=未配置
```

随时查状态：

```bash
curl -s http://127.0.0.1:8000/health | python3 -m json.tool
# {"status":"ok", ..., "qq_bot":{"enabled":true,"running":true,"app_id":"...","sandbox":true,"scene_stats":{...}}}
```

**不填凭证也能测**：`QQ_BOT_ENABLED=false` 时，机器人命令逻辑通过 HTTP 就能验证——

```bash
curl -X POST http://127.0.0.1:8000/api/v1/bot/command \
  -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -d '{"text":"STM32 还有多少","operator":"qq:10001","scene":"qq-c2c"}'
```

这条路和 QQ 真实消息走的是**同一个 `CommandRouter`**，所以命令解析的行为可以先离线确认。

## 四、QQ 里能用的指令

| 指令 | 例子 |
|---|---|
| `帮助` | 列出全部指令 |
| `库存` | 在库总览（分类汇总）**+ 具体物品清单** |
| `查 <关键词>` | `查 0.1uF`、`查 STM32`、`查 电容` |
| `入库 <名称> <数量> [@位置] [#别名] [（规格）]` | `入库 STM32F103C8T6 25 @A柜-1层-盒3 #F103C8 (LQFP48)` |
| `出库 <名称> <数量>` | `出库 F103C8 5` |
| `盘点 <名称> <数量>` | `盘点 0.1uF 480` |
| `位置 <位置名>` | `位置 A柜-2层-盒1` |
| `别名 <名称> +<别名>` | `别名 STM32F103C8T6 +蓝药丸` |
| `库存不足` | 列出数量 ≤ 5 的物品 |
| `STM元器件` / `游戏卡` / `分类 游戏卡` | 看某个分类下的**在库**清单 |
| `零库存` | 看已出库（数量为 0）的条目 |
| `清理零库存` | 删掉这些空记录（**需要二次确认**） |
| `采购 <清单>` | 拿采购清单对比库存，输出该买什么、已有物品在哪、还差多少 |
| `导入` / 直接粘贴清单 | 把整份清单粘给机器人，解析后让你确认 |
| `归类 <名称> <分类>` | 改分类；也可说「杜邦线归入stm元器件」；分类不存在会自动新建 |
| `删除 <名称>` / `删除全部` | 删记录 / 清空（**都需要二次确认**） |
| `整理` | 让 AI 通读在库条目，提出补封装/补别名/归类建议（**需要二次确认**） |
| `出库全部` / `清空库存` | 整批清零（**需要二次确认**） |
| 自然语言 | `STM32 还有多少`、`游戏卡放哪了`、`A柜里有什么`、`总共多少种物品` |

### 出库 / 盘点 也能接一整张清单

不用一条一条发 —— 把清单贴在动词后面就行，执行前照样让你确认：

```
用户：出库
      R 51Ω 0.25W 直插（直插） × 200
      R 220Ω 0805（0805） × 200
      R 10k 0.25W 直插（直插） × 200

机器人：将按清单批量出库 3 项：
          · R 51Ω 0.25W 直插（直插）  200 → 0
          · R 220Ω 0805（0805）  200 → 0
          · R 10k 0.25W 直插（直插）  200 → 0

        回复「确认」执行，或「取消」放弃。
```

三种写法都认：

| 写法 | 说明 |
|---|---|
| 直接复制机器人的清单 | 行首序号 / 项目符号会自动去掉，`（规格） × 数量 @位置` 原样识别 |
| Markdown 表格 | `\| 名称 \| 数量 \|`，表头自动识别 |
| 逐行 `名称 数量` | `出库 NE555 30` |

- **执行前一定确认**；回复「取消」就当没发生
- 脚本化的「一条库存不足」**不会拖累其他条目**：能出的照常出，失败的在结果里逐条列出
- 对不上的条目（库存里没有 / 有多个候选 / 没写数量）会在预览里单独列出来，不会静默跳过
- `盘点` 同理，是把数量**改成**清单里的值

### AI 模糊指令匹配

规则（关键词/别名表）是第一道；**规则认不出来的说法会交给大模型判断意图**，再分发到正确的命令。

实测（真实 DeepSeek）：

| 用户说 | 结果 | 走哪条 |
|---|---|---|
| `清除全部` | 整批出库 | 规则（`清除` 已在动词表里） |
| `全部不要了` | 整批出库 | **AI 判成 `out_all`** |
| `给我看看家底` | 库存总览 | **AI 判成 `overview`** |
| `手头还有多少东西` | 库存总览 | **AI** |
| `有哪些快见底了` | 没有库存 ≤ 5 的物品 | 规则（空结果本身就是答案，不再问 AI） |
| `那个东西呢` | 没找到…（不乱执行） | **AI 明确回 `unknown`** |

安全设计：

- **只在规则确实没看懂时**才问 AI：`unknown`，或「按名称找/统计/问位置」但一条都没命中。
  像 `low_stock`、`list` 这种「空结果本身就是答案」的意图不会去问 AI
- AI 宁可不答：**拿不准就回 `unknown`**，退回原来的「没找到」提示，绝不硬猜着执行
- **会改库存的意图门槛更高**（confidence ≥ 0.75，默认阈值 0.5）且必须给出名称，
  数量说不清时转交给库存解析去追问，而不是瞎记一个数
- 破坏性操作（整批出库、清空记录、清理零库存）**一律还要二次确认**

开关：`QQ_AI_INTENT=false` 可关掉。

### 合并重复条目

`整理` 会把「可能是同一种东西」的分组**编号列出**，并告诉你怎么合并：

```
用户：整理
机器人：我看了一遍当前在库的条目，建议改 1 处：
        …
        另外这几组可能是同一种东西（我不会自动合并）：
          1. 100欧姆电阻（0805） @ C库 × 200 ≈ 100Ω电阻（0805） @ C库 × 100
        要合并就回「合并 1」，或「合并这些」全部合并；也可以自己手动处理。

用户：合并 1
机器人：将合并 1 组：
          保留：100欧姆电阻（0805） @ C库 × 200
          并入：100Ω电阻（0805） @ C库 × 100
          → 合并后 300 件，被并入的名称会留成别名

        回复「确认」执行，或「取消」放弃。
用户：确认
机器人：已合并：
          · 「100欧姆电阻」现在 300 件 @ C库，并入了 100Ω电阻（别名 +100Ω电阻）
```

- **数量相加**（合并前后总库存不变，所以只写审计、不写库存流水）
- **被并入记录的名称与别名都会留成别名** —— 合并后搜旧写法照样找得到
- 保留哪条：整理出来的分组会自动挑「信息最全」的那条（有规格 > 别名多 > 数量多 > 先建的）；
  手动指定则用 `合并 <要并掉的> 到 <保留的>`（也认「把 A 合并到 B」）
- **规格不同会先警告**：`0805` 和 `SOP-8` 很可能真的是两种东西，提醒你别误合并
- 执行前一定确认，回复「取消」就当没发生

### 归类与删除

```
用户：杜邦线归入stm元器件
机器人：已把「杜邦线」从「未分类」改到「stm元器件」（新建了分类「stm元器件」）

用户：归类 杜邦线 耗材
机器人：已把「杜邦线」从「stm元器件」改到「耗材」（新建了分类「耗材」）
```

> **没有内置分类** —— 你说什么分类名就建什么分类。分类列表随时可以用 `分类`（不带参数）或
> `GET /analysis/categories` 查；写不全也没关系，`分类 游戏卡` 能匹配到 `Steam游戏卡`。

分类不存在时会**自动新建**（这就是「AI 自动创建类别」的手动入口）。
新建的分类立刻能用于 `分类 耗材`、统计和过滤。

```
用户：删除 杜邦线
机器人：将删除「杜邦线」（15 件）。出入库流水会保留，但这条物品记录本身不再存在，且无法恢复。
        回复「确认」执行，或「取消」放弃。

用户：删除全部
机器人：⚠️ 这会删除**全部 9 条**物品记录：
        涉及：STM32F103C8T6、100欧姆电阻、……
        出入库流水和审计日志会保留，但物品记录无法恢复。
        回复「确认」执行，或「取消」放弃。
```

### 入库后面跟一整张表格 = 批量导入

粘贴表格时**不要**加 `入库` 前缀（加了也认，会自动转成导入预览），直接粘就行；
或者用 `导入` 命令。`出库` / `盘点` 后面接表格会被拒绝并提示正确用法 ——
它们一次只能处理一个物品。

### 采购清单比对（`采购`）

把采购清单发给机器人，它对比库存后告诉你：**哪些够了（在哪个位置、多少件）、哪些还差多少、哪些完全没有**。

```
用户：采购
      | 名称 | 数量 |
      | --- | --- |
      | STM32F103C8T6 | 25 |
      | 0.1uF 50V MLCC | 1000 |
      | ESP32-C3 | 5 |

机器人：对照采购清单：3 项 —— 已够 1，不足 1，缺 1

        【已够】
          ✓ STM32F103C8T6  需要 25 / 现有 25
              @ A柜-1层-盒3 × 25（LQFP48）

        【不足，需要补】
          ⚠ 0.1uF 50V MLCC  需要 1000 / 现有 500　还差 500
              @ A柜-2层-盒1 × 500（0805）

        【库存里没有】
          ✗ ESP32-C3  需要 5

        需要额外购买：
          · 0.1uF 50V MLCC × 500
          · ESP32-C3 × 5
        合计 2 项 / 505 件
```

- 表格可以直接从 Excel 粘贴；也支持一行一个：`采购 STM32F103C8T6 25, NE555 10`
- **同一个物品放在多个位置时，每个位置各列一行**，数量自动汇总
- 只把**匹配到 0.9 分以上**的条目算作「已有」（`100欧姆电阻` 与 `100Ω电阻` 算同一条）
- 清单里没写数量时只报「现有多少」，不计入采购量

### 入库已有物品：位置怎么处理

**入库已经有记录的物品时，不用重复填位置** —— 直接累加，位置保持原样：

```
用户：入库 STM32F103C8T6 5
机器人：入库成功：STM32F103C8T6（LQFP48） 25 → 30，位置 A柜-1层-盒3
```

**但如果你填了一个不同的位置，机器人不会默默丢掉它**，而是问你：

```
用户：入库 STM32F103C8T6 5 @B柜-9层
机器人：「STM32F103C8T6」已经有一条记录了：
          @ A柜-1层-盒3 × 25

        你这次填的位置是「B柜-9层」，要怎么处理？
          ① 合并 —— 把位置改成 B柜-9层，只保留一条
          ② 分开 —— 在 B柜-9层 另建一条，原来那条不动

        回复「合并」或「分开」（回复「取消」放弃本次入库）。
```

- 问询期间**不会落库**，回复「取消」就当没发生
- 选「合并」= 把原来那条的位置改掉（只留一条）
- 选「分开」= 同一物品在两个位置各一条记录（分仓存放），别名会一起复制过去
- HTTP 侧对应 `merge_location: true/false`；不传时返回 **409 `location_conflict`** 并附上现有记录信息

### 换了封装 = 另一种东西

**已有记录填了不同的封装时，会单独建档**，不会被并进同一条：

```
用户：入库 100Ω电阻 200
机器人：入库成功：100欧姆电阻（0805） 120 → 320，位置 C库

用户：入库 100Ω电阻（SOP-8） 200
机器人：新建并入库成功：100欧姆电阻（SOP-8） 0 → 200，位置 C库
        （别名 100Ω电阻 一起带过去了）
```

- **补全**（原记录没封装、你补一个）算补全，不会新建品种
- 封装写一样时照常累加
- 物品的唯一身份 = **名称 + 位置 + 规格**；三者之一不同就是不同的记录

### AI 语义解析（听得懂人话）

默认 `QQ_PARSE_MODE=auto`：规则解析负责常见写法，**解析不出来时才交给大模型**。
想在 `入库/出库` 上完全依赖 AI，把 `.env` 改成 `QQ_PARSE_MODE=ai`。

```
用户：昨天进了一盒 100欧姆电阻 放在 C库，是 0805 的
机器人：新建并入库成功：100欧姆电阻（0805） 0 → 1，位置 C库
        （AI 理解：进货一盒，数量1，0805规格，C库）
```

**数量说不清楚时机器人会反问，而不是瞎记**：

```
用户：入库 杜邦线 一些
机器人：我理解你是要入库「杜邦线」，但没听出数量。
        （AI 判断：明确入库，数量只说“一些”未给具体数字）
        补一句就行，例如：入库 杜邦线 10
```

AI 还能**创建新分类**（分类不是封闭枚举）：

```
用户：进了一块 ESP32-C3 开发板 放 A柜
机器人：新建并入库成功：ESP32-C3 开发板 0 → 1，位置 A柜
        （已归入新分类：开发板）
```

`QQ_AI_CONFIDENCE`（默认 0.5）是自动执行的可信阈值；低于它就不落库，退回规则解析。

### 直接在聊天框发文件

不用走 HTTP 接口，**在 QQ 聊天框里直接把文件发给机器人**就行（单聊和群聊都支持）：

```
用户：[发送 库存清单.xlsx]
机器人：我从「库存清单.xlsx」里解析出 2 条记录：
          AMS1117-3.3（SOT-223） × 50 @ D柜-1层
          1N4148（DO-35） × 200 @ C柜-2层

        回复「确认」导入（同名同位置的数量会被覆盖），或「取消」放弃。
用户：确认
机器人：导入完成：共 2 条，新建 2，更新 0
```

- 支持 **`.xlsx` / `.xlsm` / `.csv` / `.txt` / `.log` / `.md` / `.json`**（旧版 `.xls` 请先另存）
- 用的是和 HTTP 上传、粘贴导入**完全同一套解析器**
- **导入前 AI 会通读整批做预处理**：规范命名 + 自动归类（没有的分类自动新建），预览里会写明
- 改名时**原名保留为别名**，搜旧写法照样能找到；且 AI 把名字改丢信息时会被护栏拦下
- 单文件上限 `QQ_MAX_FILE_MB`（默认 20MB），超了会明确告诉你
- **图片**暂时看不懂（需要视觉模型），**语音/视频**也处理不了 —— 都会回明确提示，不会装死
- 确认前不落库；导入结果会写明新建/更新了几条

### 把整份清单粘给机器人

不用上传文件，直接把 Excel 里复制出来的表格、或者随手记的清单粘进 QQ：

```
用户：| 名称 | 数量 | 位置 | 规格 | 别名 |
      | --- | --- | --- | --- | --- |
      | AMS1117-3.3 | 50 | D柜-1层 | SOT-223 | 1117 |
      | 1N4148 | 200 | C柜-2层 | DO-35 | 4148 |
机器人：我从这段内容里解析出 2 条记录：
          AMS1117-3.3（SOT-223） × 50 @ D柜-1层
          1N4148（DO-35） × 200 @ C柜-2层

        回复「确认」导入（同名同位置的数量会被覆盖），或「取消」放弃。
用户：确认
机器人：导入完成：共 2 条，新建 2，更新 0
```

用的是和 HTTP 上传**同一套解析器**（`app/services/importer.py`），
所以 Markdown 表格 / `名称 × 数量 @位置` 行内式 / `### 名称 + 数量: N` 键值块都认。
二进制文件（`.xlsx`/`.csv`）仍然走 HTTP 接口上传。

### `整理`：AI 归类与规范化

```
用户：整理
机器人：我看了一遍当前在库的条目，建议改 5 处：
        （补齐可识别的规格与别名）
          · NE555：spec （空） → DIP-8；别名 +555定时器
          · Steam 50元充值卡：spec （空） → 50元
          · 100欧姆电阻：别名 +100Ω、101

        另外这几组可能是同一种东西（我不会自动合并，你确认后可以手动处理）：
          · 100欧姆电阻 ≈ 100Ω电阻

        回复「确认」应用这些修改，或「取消」放弃。
```

**确认前不会改任何数据**；重复条目只提示不自动合并，避免误合并。

### 清单只显示「在库」物品

数量为 0 的条目不再出现在 `库存` / `分类` / `位置` 清单里（只在末尾提示
「另有 N 种已清零」），要看它们用 `零库存`：

```
库存总览：在库 3 种，共 171 件，11 个位置
  · STM元器件：2 种 / 21 件
  · 其他：1 种 / 150 件
  （另有 14 种已清零，回复「零库存」查看）

物品清单：
1. 杜邦线 × 50
2. AT24C02（SOP-8） × 20 @ C柜-2层
```

搜索（`查`）刻意**保留**已清零的条目 —— 「这个料号存在、只是没货了」本身是有用信息，
列表里会标注「（已清零）」。

### 入库后追问细节（封装 / 别名）

第一条入库缺封装时，机器人会接着问：

```
用户：入库 AT24C02 20 @C柜-2层
机器人：新建并入库成功：AT24C02 0 → 20，位置 C柜-2层

        「AT24C02」要补充规格/封装吗？（例：LQFP48、0805、DO-35、SOT-223、50元）
        没有这回事就直接回「跳过」（比如游戏卡、日用品）。
用户：SOP-8
机器人：已记录规格：SOP-8

        「AT24C02」还有别的叫法吗？多个用逗号分隔（用于模糊匹配）。
        没有就回「跳过」
用户：AT24C02N, 24C02
机器人：已记录别名：AT24C02N、24C02
        信息补全完成 ✓
```

- 一次只问一个字段；回「跳过」即跳过，**同一会话里不再重复问该字段**
- 问话内容跟着分类走（Steam 卡问「面额/规格」）
- 追问期间直接下指令（如 `库存`）不会被当成答案吞掉
- 想在 `.env` 里关掉：`QQ_ASK_ON_STOCK_IN=false`

### 位置可以省略

`入库 杜邦线 100` 直接可用（位置留空）。想显式说明也可以：

```
入库 杜邦线 100 无位置
入库 排针 50 跳过位置
入库 跳线 20 不指定位置
```

反过来，位置**不写 `@` 也能识别**：`入库 100欧姆电阻 100 C库` ——
只要尾部那段含「柜/层/盒/架/箱/抽屉/库/区」就当作位置；
而 `八方旅人 随身包` 这种带空格的名称不会被误拆。

### 同义写法会自动归并

```
用户：入库 100欧姆电阻 100 @C库
用户：查 100Ω电阻
机器人：「100Ω电阻」找到 1 条：
        1. 100欧姆电阻 × 100 @ C库
用户：出库 100Ω电阻 30
机器人：出库成功：100欧姆电阻 0 → 100 → 70
```

`100欧姆` 和 `100Ω` 会被解析成同一个物理量再比较，
所以两种写法指向同一条记录；第一次用另一种写法命中时，
它会被**自动记成别名**（`source=auto`），之后就是精确命中。

### 位置可以不用写 `@`

`入库 100欧姆电阻 100 C库` 也能正确识别出位置 —— 只要尾部那段含
「柜/层/盒/架/箱/抽屉/库/区」这类特征词。名称里本来就带空格的
（如 `八方旅人 随身包`）不会被误拆。

### 多轮上下文

机器人会把「刚列出来的那批东西」记在会话里（群聊按群、单聊按人，15 分钟过期）：

```
用户：库存
机器人：库存总览：… 物品清单：
        1. STM32F103C8T6（LQFP48） × 25 @ A柜-1层-盒3
        2. 0.1uF 50V MLCC（0805） × 500 @ A柜-2层-盒1
        …
用户：2                     ← 直接回序号，看第 2 项详情
用户：这些全部出库            ← 「这些」= 上一次列出来的那批
机器人：将执行整批出库：全部库存，14 种物品，共 1872 件，执行后数量全部归零。
        涉及：…
        回复「确认」执行，或「取消」放弃。
用户：确认                   ← 危险操作必须二次确认
```

**模糊匹配列候选时同理**：

```
用户：出库 AMS1117-3.3 5
机器人：「AMS1117-3.3」在 2 个位置都有库存，请指定位置
        1. AMS1117-3.3 × 10 @ D柜-1层
        2. AMS1117-3.3 × 20 @ D柜-2层
        回复序号即可继续出库 5，或说得更具体一点。
用户：2                     ← 直接在选中的那条上完成出库
```

整批操作的作用范围：

| 说法 | 范围 |
|---|---|
| `出库全部`、`清空库存` | 全部库存 |
| `这些全部出库`、`上面那些都出库` | 上一次列出来的那批 |
| `STM元器件 全部出库`、`游戏卡全部清空` | 该分类下的全部 |

> 安全设计：`出库 全部电容` 这种带具体限定的说法**不会**被当成整批请求，
> 避免一句话误清空全库。

## 五、代码结构

```
app/qq/
├── types.py      # IncomingMessage / BotReply / MessageHandler
├── protocol.py   # 纯函数：握手报文、事件解析、白名单、地址解析
├── openapi.py    # access_token 换票（缓存 + 提前 60s 刷新）、C2C/群消息下发
├── gateway.py    # WebSocket 常驻循环：HELLO → IDENTIFY/RESUME、后台心跳、重连退避
└── bot.py        # 编排：白名单 → 前缀剥离 → handler → 按场景回复
```

接线在 `app/main.py` 的 `_start_qq_bot()`：

```python
async def handler(message) -> str | None:
    response = await context.commands.handle(
        message.content, operator=message.user_openid, scene=f"qq-{message.scene}"
    )
    return response.reply
```

要换成别的机器人框架（OneBot / NoneBot / 官方 Webhook），
只需要把「消息 → `commands.handle(text, operator, scene)` → 回复」这三步接上，
业务代码一行都不用改。

## 六、故障排查

| 现象 | 可能原因 / 处理 |
|---|---|
| 日志出现「QQ 机器人已启用但适配层不可用」 | 缺 `aiohttp`，`pip install aiohttp` |
| `access_token` 换票失败 | AppID/AppSecret 错误；或该机器人只有 token，改填 `QQ_BOT_TOKEN` |
| 连上了但收不到消息 | `QQ_INTENTS` 订阅位不对（群/单聊要含 `1<<25`）；或机器人未开通对应场景 |
| 能收到消息但回复失败 | 被动回复有**时间窗口和条数限制**，超时后需要走主动消息（本服务未实现主动推送，因为要申请权限） |
| 沙箱能通、正式不通 | 沙箱和正式是两套环境，`QQ_SANDBOX` 要跟着切，白名单 openid 也不同 |
| 频道消息没有回复 | 项目对 guild 场景只接收不主动回复（需要额外权限，见代码注释） |

## 七、诚实声明：哪些验证过、哪些没有

**已验证**（`python3 scripts/check_qq.py`，25/25 通过）：

- 握手报文结构（IDENTIFY / RESUME / HEARTBEAT）
- 事件解析：`C2C_MESSAGE_CREATE` / `GROUP_AT_MESSAGE_CREATE` / 频道消息，以及缺字段、未知事件的健壮性
- `@机器人` 提及清洗、白名单四种组合
- 消息编排：前缀剥离、handler 异常被吞掉并返回友好文本、白名单外不回复
- 网关纯函数：payload 分类、指数退避上限

**未验证**（没有线上凭证，一行都没跑过）：

- `access_token` 真实换票流程、`expires_in` 语义
- `POST /v2/users/{openid}/messages`、`POST /v2/groups/{group_openid}/messages` 的
  端点与请求体是否与线上完全一致
- WebSocket 真实握手、心跳时序与 ACK、OP7/OP9 处理、断线重连退避
- 为防半开连接设置的 HELLO 30s 超时与 `/gateway` GET 15s 超时是否合适

拿到凭证后请**先开 `QQ_SANDBOX=true`** 试，观察 `uvicorn` 日志里网关连接与心跳是否正常。
如果有出入，改动会集中在 `app/qq/openapi.py` 与 `app/qq/gateway.py`，不影响库存业务代码。
