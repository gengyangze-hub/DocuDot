# QQ 指令速查

> 全部 22 个命令、82 个别名（**与 `app/bot/commands.py:COMMAND_ALIASES` 逐条核对过**，22/82 一致）。
> 命令名与别名以代码为准；本文档是人工整理的用法说明，不含全部冷门别名。
> **大部分时候你不用记命令** —— 直接说人话也行，见第三节。

## 一、入库 / 出库 / 盘点

| 你想要什么 | 可以这样说 | 备注 |
|---|---|---|
| 入库 | `入库 NE555 30`、`进货 NE555 30 @C柜-1层`、`收 NE555 30` | 位置可省略；别名用 `#F103C8`，封装用 `（LQFP48）` 或直接裸写 |
| 出库 | `出库 NE555 5`、`领用 NE555 5`、`用掉 NE555 5` | 库存不足会拒绝并告诉你差多少 |
| 盘点（直接改数量） | `盘点 NE555 42`、`设为 NE555 42`、`更正 NE555 42` | 是「改成 42」，不是加减 |
| **批量出库** | `出库` + 粘贴一整张清单 | 表格 / 逐行 / 把机器人列出的清单复制回来都认 |
| **批量盘点** | `盘点` + 粘贴清单 | 同上 |
| 整批清零 | `出库全部`、`清空库存`、`清除全部`、`全部不要了` | **需要确认**；只把数量归零，记录还在 |
| **处置上一批** | `这些全部出库`、`把采购清单里的物品删掉`、`好的，现在从库存里面删除这些` | **清零 vs 删除分得清**，见下 |

```
入库 100Ω电容 0805 100        ← 0805 会自动认成规格，不会再追问一次
入库 STM32F103C8T6 25 @A柜-1层 #F103C8 (LQFP48)
出库
| 名称 | 数量 |
| --- | --- |
| R 51Ω 0.25W 直插 | 50 |
| R 220Ω 0805 | 80 |
```

### 「这些」怎么处置 —— 清零还是删除

跑完 `采购` 或列出清单后，用「这些」「采购清单里的物品」指代它们：

| 你说 | 结果 |
|---|---|
| `这些全部出库` / `把采购清单里的物品清掉` / `我要用掉` | **出库清零**（数量归零，记录保留，之后可「清理零库存」删） |
| `好的，现在从库存里面删除这些` / `把采购清单里的物品删掉` | **真的删掉记录**（不可恢复） |
| `把这些处理掉`（没说清） | **反问**：列出「这些」具体是哪些，让你选 ① 出库清零 ② 删除记录 |

```
你：把这些处理掉
机器人：「这些」指的是采购清单里已拥有的物品的 2 种物品（排母 11P、1kΩ），共 400 件。

        要我怎么处理？
          ① 出库清零 —— 数量归零，记录保留（之后还能用「清理零库存」删）
          ② 删除记录 —— 记录直接删掉，无法恢复

        回复「出库」或「删除」，也可以回「取消」。
你：出库
机器人：将执行整批出库：… 回复「确认」执行，或「取消」放弃。
```

**同一个物品的判定**：`名称 + 位置 + 规格` 三者都相同才是同一条。
入库已有物品时**不用重复填位置**（直接累加）；填了新位置会问你「合并 / 分开」；
换了封装则**单独建档**（不同封装是不同东西）；原来没规格时填规格算「补全」。

## 二、查询与统计

| 你想要什么 | 可以这样说 |
|---|---|
| 库存总览（分类汇总） | `库存`、`总览`、`概况`、`库存总览`、`统计` |
| 在库清单（带序号，**可以回序号继续操作**） | `清单`、`列表`、`所有物品`、`全部物品` |
| 按名称找 | `查 STM32`、`搜索 电容`、`找 杜邦线` |
| 按分类看 | `分类 STM元器件`、`类别 耗材` |
| 按位置看 | `位置 A柜`、`库位 C库` |
| 零库存条目 | `零库存`、`空库存`、`已出库`、`已清零` |
| 库存偏低 | `库存不足`、`低库存`、`缺货`、`补货` |
| 看 / 加别名 | `别名 NE555` |
| 帮助 | `帮助`、`菜单`、`指令`、`用法` |
| 出入库流水 | 走 HTTP `/api/v1/stock/movements`（QQ 里没有对应命令） |

> `库存` 是**汇总 + 清单**（分类各多少种多少件，后面跟逐条清单），`清单` 是只看逐条清单。
> 两者都带序号，都可以回「2」看第二条详情。

`查` 支持模糊匹配与物理量等价，**同一个东西的多种叫法都能命中**：

```
查 电阻        查 R        查 欧姆      ← 三种说法命中同一批
查 插排        查 排母      查 排针      ← 连接器的几种叫法也等价
查 10kΩ        查 100nF 0805             ← 数值/封装组合
查 STM32       查 单片机                  ← 型号前缀推断类型
```

## 三、直接说人话（不用记命令）

规则先跑；**规则认不出来时交给大模型判断意图**，再分发到正确命令。

| 你说 | 会发生什么 |
|---|---|
| `全部不要了` | 整批出库（AI 判成 `out_all`） |
| `给我看看家底` / `手头还有多少东西` | 库存总览 |
| `有哪些快见底了` | 低库存清单 |
| `进了两盒杜邦线放A柜` | 入库（AI 解析出名称/数量/位置） |
| `我把 0.1uF 电容用掉了一些` | 出库；数量说不清会**反问**而不是瞎记 |
| `昨天进了一盒 100欧姆电阻 放在 C库，是 0805 的` | 入库并填好规格 |
| `杜邦线归入stm元器件` | 改分类（分类不存在会自动新建） |
| `把 A 合并到 B` | 合并两条记录 |
| 直接粘贴一段表格 | 自动转成导入预览 → 确认后入库 |
| 直接发文件（`.xlsx`/`.csv`/`.txt`/`.md`/`.json`） | 下载 → 解析 → AI 归类+规范命名 → 确认后入库 |

**AI 只在这里介入**：意图判断、库存描述解析、导入归类与规范命名、`整理`、追问是否需要。
它**拿不准就明确说不知道**，退回「没找到」提示，不会硬猜着执行。

## 四、清单类操作

| 命令 | 说明 |
|---|---|
| `采购 <清单>` | 拿采购清单对比库存：哪些够了（在哪、多少）、还差多少、需要买什么 |
| `对单 <清单>` / `缺料 <清单>` / `要买什么 <清单>` | 同上 |
| `导入` | 把整份清单粘给机器人（表格 / 行内式 / 键值块都行） |
| `整理` | 让 AI 通读在库条目，提出补规格 / 补别名 / 归类建议；**数量不足或可能是重复**的会单独列出 |
| `合并 1` / `合并这些` | 把 `整理` 找出的重复分组真的合并（数量相加、名称留成别名） |
| `合并 <要并掉的> 到 <保留的>` | 手动指定两条合并 |

### 采购支持封装

**清单里写了规格，就按规格算** —— 要 `0805` 的不会拿 `0603` 的库存顶上：

```
采购
| 名称 | 数量 | 规格 |
| --- | --- | --- |
| 100nF 50V | 1000 | MLCC 0805 |

⚠ 100nF 50V（MLCC 0805）  需要 1000 / 现有 200　还差 800
    @ （未指定位置） × 200（MLCC 0805）
```

- 不写规格 = 汇总所有封装（「有没有这个东西」的粗查）
- 规格对不上时会告诉你 **「有同名但封装不同：0603」**，不会让你以为数据丢了
- 多词名称（`排母 11P`）现在也能正确命中，不会因为长度比被压到门槛之下

```
采购
| 名称 | 数量 |
| --- | --- |
| STM32F103C8T6 | 25 |
| 0.1uF 50V MLCC | 1000 |

整理          → 建议改 N 处 + 「可能是同一种东西」的分组
合并 1        → 预览保留/并入 + 合并后数量 → 确认
```

## 五、归类与删除

| 命令 | 说明 |
|---|---|
| `归类 <名称> <分类>` | 改分类；分类不存在会**自动新建** |
| `杜邦线归入stm元器件` | 同上（自然说法） |
| `删除 <名称>` | 删一条记录，**需要确认** |
| `删除全部` / `清空全部` | 清空所有记录，**需要确认 + 明确警告** |
| `清理零库存` / `删除零库存` | 只删数量为 0 的条目，**需要确认** |

## 六、多轮上下文

机器人记得你上一条说了什么：

- 列出清单后回**序号**继续操作：`2`、`第2个`、`1、3`
- 说**「这些」**指代上一次列出的物品：`这些全部出库`
- 入库后追问封装/别名，回**「跳过」**不填
- 有待确认操作时，回 `确认` 执行、`取消` 放弃
- `整理` 之后可以直接回 `合并 1`（不会被待确认卡住）

会话默认 900 秒过期；群聊里上下文按「群」共享，单聊按用户。

## 七、哪些操作需要二次确认

不会静默改数据的操作：

| 操作 | 确认方式 |
|---|---|
| 整批出库 / 清空库存 / 清除全部 | 回复「确认」 |
| 按清单批量出库 / 盘点 | 回复「确认」 |
| 合并记录 | 回复「确认」 |
| 删除条目 / 删除全部 / 清理零库存 | 回复「确认」 |
| 应用 `整理` 建议 | 回复「确认」 |
| 入库时位置不同（合并还是分开） | 回复「合并」或「分开」 |
| 导入预览 | 回复「确认」 |

**直接执行**（因为可逆或只是查询）：单条入库/出库/盘点、归类、查询、搜索、`采购` 对比。

## 八、相关配置

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `QQ_PARSE_MODE` | `auto` | `auto` 规则优先、AI 兜底；`rules` 纯规则；`ai` 出入库一律问 AI |
| `QQ_AI_CONFIDENCE` | `0.5` | AI 结果可信阈值（改库存的意图要求 ≥0.75） |
| `QQ_DETAIL_PROMPTS` | `auto` | 追问策略：`auto` / `always` / `never` |
| `QQ_AI_INTENT` | `true` | 规则认不出时是否让 AI 做模糊指令匹配 |
| `AI_CLASSIFY_ON_IMPORT` | `true` | 导入时 AI 自动归类（新分类自动创建） |
| `AI_NORMALIZE_ON_IMPORT` | `true` | 导入时 AI 规范命名（原名保留为别名） |
| `QQ_MAX_FILE_MB` | `20` | QQ 里直接发文件的大小上限 |
| `QQ_ALLOWED_USERS` / `QQ_ALLOWED_GROUPS` | 空 | 白名单，留空不限制 |
| `QQ_COMMAND_PREFIX` | 空 | 群里必须带的前缀，留空表示整条消息直接解析 |
